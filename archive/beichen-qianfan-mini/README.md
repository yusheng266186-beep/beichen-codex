# 北辰 · 高一选科探索

> 譬彼北辰，居其所而众星共之。——《论语·为政》

北辰是一款面向高一学生的 AI 选科探索网页。它不从“哪个组合更热门”开始，而是通过十轮谈心，陪使用者回看学科手感、开窍与挫败、真正的热爱、理想生活、家庭声音和个人边界，最后点亮一张属于自己的「北辰星图」。

> 在线体验：[打开北辰](https://yusheng266186-beep.github.io/beichen/) · 项目仓库：[查看源代码](https://github.com/yusheng266186-beep/beichen)

## 项目定位

高一选科既是一次学科组合选择，也是许多学生第一次认真回答“我适合怎样的学习方式、以后想走向哪里”。

北辰希望解决的不是单一的文理判断，而是三个更具体的问题：

- 哪些学科是真正有手感，而不只是暂时成绩较高；
- 哪种学习强度、思维方式和未来生活更适合自己；
- 在专业覆盖率、升学稳定性、个人热爱和现实条件之间，应该怎样理解取舍。

页面的最终结果是探索参考，不是替使用者作决定的测评结论。它适合用于形成问题、整理线索和开启亲子或师生讨论。

## 为什么叫「北辰」

北辰不是夜空中最亮的星，却长期被人用来辨认方向。

选科也很像一次夜行：成绩、兴趣、家长期待、专业门槛和同学选择都在发出声音，而真正需要被看见的，是使用者心里那颗相对稳定的“定星”。因此，页面没有把过程设计成冰冷问卷，而是用「初见、底色、热爱、远方、星图」五幕承接十轮对话。

星星只指方向，路仍然要自己走。

## 完整体验流程

### 1. 星门验证

- 通过提供的 6 位动态验证码进入；
- 验证成功后，本设备在有效期内可以直接继续使用；
- 一次验证可完成 3 次完整谈心，以星图生成为一次；次数由云端 Token 记录；
- 星图生成后的追问不额外计次；
- 达到 3 次后，下一轮完整探索需要重新验证；
- 星图底部会以小字提示本次使用额度，导出图片时不会带上这行提示。

### 2. 关于北辰

首次验证和每次重新验证成功后都会展示序章，说明项目名字、谈心方式和星图含义；同一轮验证有效期内刷新页面不会重复展示。

### 3. 十轮谈心

对话从真实经历出发，依次靠近：

1. 学科的轻松感、困难感和当前基础；
2. 某门学科开窍或越学越吃力的经历；
3. 最近一次做到忘记时间的事情；
4. 推导、阅读、表达等思维舒适区；
5. 对高二不同学习强度的承受感；
6. 希望以什么方式参与世界；
7. 心动或排斥的职业方向；
8. 家庭期待、分歧和外界声音；
9. 自己眼中的性格与行动方式；
10. 专业选择面与升学稳定性之间的取舍。

每轮都支持点击 4 个快捷选项，也支持直接输入自己的真实情况。AI 会先回应上一段回答，再自然进入下一段谈心。

### 4. 点亮北辰星图

谈心结束后生成完整星图，包括：

- 专属称号与一句话画像；
- 文科—理科方向轴、星标位置、星值分数和偏向说明；
- 学科底色；
- 思维与学习方式；
- 热爱与职业方向；
- 决策工具透视；
- 盲区、耗电点与提醒；
- 3+1+2 首选组合与备选组合；
- 专业覆盖率和可继续调研的专业方向；
- 一段结合本次回答写给使用者的寄语。

报告文字会使用“你提到……”“当你说起……”等更温和的回望式表达，不在星图中反复出现“第几问”或测评式判断语气。

### 5. 继续追问

星图生成后仍可继续询问：

- 为什么更靠近这个方位；
- 两个组合应该怎样比较；
- 某个专业对选科有哪些要求；
- 自己补充新情况后，结论是否需要调整；
- 是否重新开始一轮探索并刷新星图。

## 核心功能

### 文理方向轴

- 保留完整刻度轴；
- 星标精确落在轴线上；
- 同时显示星值分数和小字解释，避免视觉上过空；
- 方向分数只用于表达本轮谈心的相对倾向，不代表能力排名。

### 星卡式报告

星图正文使用固定结构的星卡承载信息，既保证不同报告之间结构稳定，又允许模型根据学生的具体回答写出差异化内容。

### 3+1+2 组合参考

- 输出首选与备选组合；
- 对组合名称做规则归一，避免生成不存在的组合；
- 同时展示专业覆盖率量级；
- 结合学生的学科手感、兴趣和升学取舍说明推荐理由。

### 数据参考面板

内置：

- 四川新高考相关招录量级参考；
- 常见组合专业覆盖率速查；
- 黄金三角、霍兰德和 SWOT 三种决策视角；
- 常见疑问；
- 延伸阅读。

### 保存与续谈

- 保存完整星图为 2 倍清晰度 PNG；
- 复制星图全文；
- 图片导出时自动展开全部报告内容；
- 本地保存当前谈心，刷新或误关页面后可继续；
- 最终报告生成后压缩上下文，降低后续追问的重复消耗。

## 视觉与交互设计

- 以“夜空、书页、星图”为核心视觉意象；
- 使用暖色纸张、深蓝夜色、金色星光和衬线字体建立叙事感；
- 桌面端保留完整沉浸画面，手机端针对软键盘和安全区适配；
- 阶段名称采用「初见、底色、热爱、远方、星图」，弱化问卷编号感；
- 对话、弹窗、星轴、覆盖率和报告卡片使用轻量渐进动画；
- 支持系统的减少动态效果偏好；
- 关键按钮提供按压、加载、失败和完成反馈。

## 技术实现

- 原生 HTML、CSS、JavaScript；
- 单文件主应用，无框架、无 npm 构建步骤；
- GitHub Pages 静态托管；
- 腾讯云函数负责模型请求中转和跨域响应；
- Cloudflare Worker 版本作为备用中转实现；
- SSE 流式接收模型内容；
- requestAnimationFrame 节流更新页面；
- 请求超时、自动重试和报告截断续写；
- `sessionStorage` 保存短期会话 Token、额度展示和一次性完成请求 ID；`localStorage` 只保存设置与结构化谈心记录（恢复时重新用转义文本渲染，不信任 HTML）；
- 腾讯云函数负责 TOTP 校验、签发会话 Token 和记录星图次数；前端不再保存 2FA 密钥；
- html2canvas 生成完整星图图片；
- visualViewport 适配手机软键盘；
- prefers-reduced-motion 适配低动态偏好。

## 部署

### GitHub Pages

1. 将仓库推送到 GitHub；
2. 在 Settings → Pages 中选择从 main 分支发布；
3. 等待 Pages 构建完成；
4. 访问对应的 /beichen/ 地址。

### 腾讯云函数中转

1. 创建 Node.js Web 函数；
2. 使用仓库中的 `scf-relay.js` 作为函数入口逻辑；
3. 可参考根目录 `.env.example`，在环境变量中添加以下变量（均不要写回源码）。默认 provider 是 OpenCode：

       AI_PROVIDER           = opencode
       OPENCODE_API_KEY      = OpenCode API Key
       OPENCODE_MODEL        = deepseek-v4-flash（按账户可用模型填写）
       GATE_TOTP_SECRET      = 动态验证码使用的 Base32 主密钥
       GATE_SESSION_SECRET   = 随机生成的至少 32 字节长字符串
       CORS_ALLOWED_ORIGINS  = https://yusheng266186-beep.github.io
       GATE_TOKEN_TTL_MS     = 86400000（可选，默认 24 小时）
       UPSTREAM_TIMEOUT_MS   = 300000（可选，最大 300 秒）

`GATE_TOTP_SECRET` 填动态验证码的种子密钥，不是当前 6 位动态验证码。`GATE_SESSION_SECRET` 可使用密码管理器生成至少 32 字节随机字符串。
4. 若要接入百度千帆 Token Plan 个人版 Mini，将 provider 和变量改为：

       AI_PROVIDER           = qianfan
       QIANFAN_API_KEY       = Token Plan 个人版 Mini 专属 API Key（仅服务端）
       QIANFAN_BASE_URL      = https://qianfan.baidubce.com/v2
       QIANFAN_MODEL         = 账户中已开通的模型 ID

   中转会把请求发送到标准 `QIANFAN_BASE_URL + /chat/completions`（即 `/v2/chat/completions`），并在服务端注入模型名。Mini 是额度套餐/Token Plan 配置，不是模型名；`QIANFAN_MODEL` 仍须填写账户已开通的模型 ID。当前实现只允许 HTTPS hostname `qianfan.baidubce.com` 和 443 端口，避免误配环境变量形成 SSRF；如使用官方企业别名，须先在代码的 allowlist 中显式加入并重新审查。不要把密钥写入 `index.html`，不要让浏览器直连千帆。这里应使用 Token Plan 个人版 Mini 专属 key，不要替换为普通后付费 key。千帆 Coding Plan / Coding Plan Lite 的专属 key、专属接口或编码套餐端点不能作为这里的自定义后端。
5. 开启公网访问，将函数执行超时设置为 300 秒，并部署函数；`scf-relay.js` 不设置响应 socket idle timeout。`server.requestTimeout=20000` 只限制接收客户端请求体，不会在上游 20 秒无 token 时截断 300 秒流式响应。
6. 函数地址需要只暴露 `/verify`、`/chat/completions` 和 `/run/complete` 三个 POST 路径；
7. 将正式函数地址替换 `index.html` 的 `RELAY` 占位符，并同步替换 CSP `connect-src` 中的 `https://REPLACE_WITH_YOUR_RELAY_ORIGIN`；提交前必须确认页面不再保留占位符，也没有指向其他项目/旧环境的地址；
8. 依次验证：输入动态验证码、完成一张星图、刷新页面续谈、重复提交同一完成请求不会重复扣额、完成第 3 张星图后重新验证。

`relay-worker.js` 提供同等的备用中转实现。若使用 Cloudflare Worker，请在 Worker Secrets/Variables 中添加对应变量，不要把密钥写进 Worker 源码；Worker 的 `CORS_ALLOWED_ORIGINS`、`AI_PROVIDER`、`QIANFAN_*` 与上面含义相同。

### 从旧版迁移

1. 先在 provider 控制台撤销旧的、曾经出现在公开仓库或日志里的 key；旧版 token 也不再兼容。
2. 生成新的 `GATE_SESSION_SECRET`（至少 32 字节）并重新部署中转；默认 token TTL 已从 7 天收紧为 24 小时。
3. 选择一个 provider，按上面的 `opencode` 或 Token Plan 个人版 Mini `qianfan` 变量配置；Mini 是额度套餐而不是模型名。不要把普通后付费 key 或 Coding Plan/Coding Plan Lite 专属凭据填到 `QIANFAN_API_KEY`。
4. 更新 `index.html` 的 `RELAY` 与 CSP `connect-src`（新仓库默认是安全占位符，不会调用旧 `beichen` 后端）。旧浏览器中的 localStorage token 会被清理，当前标签页需重新输入 TOTP。
5. 先在测试环境验证三条精确路径、错误状态、重复 `/run/complete` 请求和超时，再切换 GitHub Pages 的正式地址。

### 公开仓库安全清单

- GitHub Pages 只托管 `index.html` 等无密钥静态文件；API key、TOTP seed、session secret 只能放在云函数/Worker 的加密 Secret 中。
- `index.html` 已为 html2canvas CDN 脚本加入 SRI；升级依赖时重新计算 `sha384` 并人工核对版本。字体和 CDN 仍是外部供应链，必要时应自托管并移除 `unsafe-inline`。
- 中转默认拒绝未知 Origin，仅允许 `CORS_ALLOWED_ORIGINS`；发布到新域名时要同时更新环境变量和页面 CSP。
- 保护 `main`：要求 Pull Request、至少一名审查者、状态检查通过、禁止强推和删除分支；启用 Dependabot/Secret scanning，并让 CI 在合并前执行语法和安全扫描。
- 无外部数据库时，session、TOTP 重放记录和额度更新只在单个运行实例内存中；这是明确的安全/可用性降级，不应被描述为跨实例全局配额。生产环境应以支持原子条件更新的 KV/数据库替代内存 Map。

### 本地检查

无需安装 npm 依赖即可执行最小检查：

    node tests/relay-smoke.test.js
    node --check scf-relay.js

    # 可选：用浏览器打开 index.html，检查控制台 CSP/SRI 和网络请求

`tests/relay-smoke.test.js` 同时执行 `scf-relay.js` 的本地无上游冒烟测试，并验证可静态加载的安全不变量（精确路径、CORS 白名单、Qianfan 标准端点、token/请求限制和不恢复 HTML）；它不会调用真实 provider，也不会证明云端部署成功。

### 密钥配置与排查

- 中转函数只在服务端读取 provider API Key、`GATE_TOTP_SECRET` 和 `GATE_SESSION_SECRET`；网页和 GitHub Pages 不保存 API Key 或 TOTP 主密钥。
- 腾讯云控制台中可在“函数配置 → 环境变量 → 导入数据”选择“json对象”，填写以下结构后保存（值替换为自己的真实值）：

      {
        "AI_PROVIDER": "qianfan",
        "QIANFAN_API_KEY": "你的 Token Plan 个人版 Mini 专属 API Key",
        "QIANFAN_BASE_URL": "https://qianfan.baidubce.com/v2",
        "QIANFAN_MODEL": "账户中已开通的模型 ID",
        "GATE_TOTP_SECRET": "你的 Base32 动态验证码主密钥",
        "GATE_SESSION_SECRET": "至少 32 字节的随机字符串",
        "CORS_ALLOWED_ORIGINS": "https://yusheng266186-beep.github.io"
      }

- Cloudflare Worker 必须把 API key、TOTP seed、session secret 存为加密 Secret，而不是普通变量；非敏感的 provider、模型、URL、CORS 可用普通变量。
- 更换密钥后，应立即在对应 provider 控制台撤销旧密钥，并重新保存中转环境变量。
- 推送前可在本地执行以下检查，确认当前文件没有明文密钥：

      rg -n --hidden --glob '!.git/**' 'sk-[A-Za-z0-9_-]{20,}' .

  正常情况下该命令不应返回任何结果。仓库早期版本曾经出现过硬编码密钥记录，因此旧密钥必须视为已暴露并保持吊销；如需清理公开 Git 历史，需要单独安排重写历史和强制推送。

## 数据与本地状态

页面会在当前浏览器保存：

- 当前标签页的短期会话 Token、有效期提示和完成请求 ID（默认 TTL 24 小时）；
- 云端返回的本次验证星图次数；
- 深度思考设置；
- 当前谈心内容；
- 已生成的星图和追问上下文。

关闭标签页、清除浏览器站点数据、使用无痕模式或更换设备后，Token 可能消失，需要重新验证。页面没有账号系统，也不提供跨设备同步。服务端无外部数据库时，session/额度/防重放状态只在当前函数实例内存中：实例重启会要求重新验证，多实例并不能提供全局额度一致性。正式公开服务应接入具备原子条件更新的 KV/数据库，或使用粘性单实例并接受该降级。

## 数据来源与口径

页面中的覆盖率、招生计划和本科率等数字，主要用于帮助学生理解不同赛道的数量级和取舍，不是录取预测。

参考来源包括：

- 四川 2025—2026 新高考招录研究资料；
- 政府公开的新高考政策解读；
- 公开的选科组合覆盖率资料；
- 院校招生章程与专业选科要求的通用规则。

不同省份、年份、院校和专业组的要求可能变化。正式选科前必须以本省考试院、目标院校最新招生章程和学校实际开班条件为准。

## 与「自我使用说明书」的区别

- **北辰**面向高一阶段，重点回答“文科还是理科、怎样选择 3+1+2 组合”；
- **自我使用说明书**面向高考志愿和专业探索，重点回答“我适合怎样的专业学习与未来工作方式”。

两个项目都从自我认识出发，但服务的决策阶段不同。

## 已知限制

- AI 输出具有随机性，同样的回答可能产生不同措辞；
- 星值和组合建议是本次谈心的解释结果，不是标准化心理测验；
- 招生数据和专业要求会随年份变化；
- 网络、中转服务或模型额度异常时，AI 对话可能暂时不可用；
- 页面不能代替学校课程指导、官方政策核对和家庭共同决策。

## 维护清单

更新项目时，建议同步检查：

1. 十轮谈心是否按顺序自然推进；
2. 生成结果中是否避免“第几问”等测评腔；
3. 星标是否准确落在方向轴上；
4. 星值分数、方向文字和组合推荐是否同时显示；
5. 三次使用额度是否正确累计；
6. 导出图片是否完整且不包含额度小字；
7. 刷新后能否恢复当前谈心；
8. 手机软键盘弹出后输入栏是否仍然可见；
9. 数据来源、模型名称和中转地址是否需要更新。
